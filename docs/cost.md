# Deterministic UI cost (`rur cost`)

`rur cost` runs a deterministic, CPU-only accounting pass over a Roblox UI scene (or a multi-frame sequence) to count the client's draw calls, quads, glyphs, clipped overdraw, Studio `CanvasGroup` render-target sizes, hidden DOM subtrees, and layout churn without initializing a GPU device or recording host wall-clock timings, and prices the UI draw pass and layout in milliseconds from slopes measured on a Roblox client.

Every `cost.json` output contains zero wall-clock fields and zero output-directory paths, so repeated runs of the same input are bit-identical even under heavy host load.

## Commands

```powershell
# Single-moment UI cost (fixture, story, module, or model)
node cli/rur.mjs cost --story path/to/Hud.story.luau --viewport 1920x1080 --scale 1.5 --out out/hud-cost

# Full PlayerGui + CoreGui cost across every enabled ScreenGui
node cli/rur.mjs cost --fixture path/to/hud.luau --all-layers --out out/hud-all

# Multi-frame sequence layout churn (CPU-only, no GPU/PNG/video)
node cli/rur.mjs cost --story path/to/Anim.story.luau --from 0.5 --frames 60 --fps 60 --out out/anim-cost

# Capture frames/video AND deterministic cost.json in one pass (pass --mode play for per-frame layoutCpuMs; default edit mode refuses it on screen)
node cli/rur.mjs sequence --story path/to/Anim.story.luau --mode play --from 0 --frames 60 --fps 60 --cost --out out/anim-seq

# Analyze a saved scene.json (note: hiddenInShown.complete is false without a live DOM)
node cli/rur.mjs cost --scene out/hud/scene.json --out out/hud-cost

# Deterministic A/B diff between two cost.json reports
node cli/rur.mjs cost compare out/before/cost.json out/after/cost.json --json
node cli/rur.mjs cost --story path/to/Hud.story.luau --compare out/before/cost.json --out out/after
```

`rur cost` delegates directly to `rur-native cost`, so standalone release binaries support every flag without Node. Without `--json`, stdout prints a compact one-screen summary (stating the two defaults `single=edit, seq=play`, labeling sequence headlines as `headline=last sample` with peak quads/glyphs/RT/overdraw printed beside them, noting on static sequences that opening/full-tree cost is on the single-moment screen, suggesting a later `--time` when a single-moment `--time 0` run is empty, disambiguating repeating printed paths by keeping the distinguishing middle segments (and appending `#index @x,y` when printed text or full paths still repeat), naming the changed objects behind per-frame layout cost in `top layout` with each driver's attributed ancestor/descendant share and the listed share of total churn, and pointing to `cost.json`) while the full deterministic JSON is written to `<out>/cost.json`; pass `--json` to print the exact pretty-printed JSON bytes written to `cost.json`. `--out` accepts either a directory (writes `<dir>/cost.json`) or a `.json` file path.

## What `rur cost` counts

### 1. Quads, glyphs, overdraw, and draw calls

- **Quads (`totals.quads`, `totals.quadsByKind`):** non-glyph UI quads broken down by kind (`solid`, `styled_fill`, `border`, `image`, `styled_image`, `shadow`, `stroke`, `scrollbar`, `group_composite`, `path2d`), counted as the client draws them: a border is 4 strips, a border `UIStroke` 4 edge quads (8, with corners, from 3 device px thick), a sliced image the cells that have an on-screen width and height (9, fewer when a `SliceCenter` edge lies on the texture's edge, when the image is no larger than its corners, or 1 at `SliceScale` 0; the texture's size is read from its file on this machine, never downloaded, and 9 is counted when it is not there), a `UIShadow` 54 (74 inset), a `Path2D` one quad per straight segment and per join between segments, and for a curved segment the client's pieces (it steps along the curve's parameter by 1/15 where that piece stays within 1 logical px of its chord, else by 1/30, a quad a step, and one quad more after a last long step: a quarter arc of any radius is 16, an S curve 23), and an element turned off the pixel axes (not a multiple of 90 degrees) gets 4 anti-aliased edge quads per quad unless it is a rounded shape.
- **Glyph quads (`totals.glyphQuads`):** visible non-space fill glyph quads (`fillGlyphQuads`: one per glyph, one per colour layer for a colour emoji, and none for an empty glyph of a colour font such as a variation selector) plus stroke glyph quads (`strokeGlyphQuads`: 4 offset copies per glyph for legacy `TextStrokeTransparency < 1`, plus 1 copy per glyph for each enabled `ApplyStrokeMode.Contextual` `UIStroke` on a text object, drawn also when the text itself is transparent) plus `shadowGlyphQuads` (1 copy per glyph for each `UIShadow` in `Mode = Text`). Clipped-out lines are excluded; `MaxVisibleGraphemes` cuts are honored.
- **Overdraw (`totals.screenOverdrawViewports`, `totals.offscreenOverdrawViewports`):** clipped physical pixel area summed over drawn quads and visible text line boxes, divided by the physical viewport area (`physicalWidth * physicalHeight`), separated into main-screen vs. `CanvasGroup` offscreen render-target overdraw. Rotated quads and rotated text lines are clipped as exact transformed polygons (Sutherland-Hodgman against the clip box and target bounds, then shoelace area) rather than axis-aligned bounding boxes, and descendants inside rotated `CanvasGroup`s are unturned into the group's own flat texture coordinates before measuring offscreen area (so a 100x100 element at 45° counts 10,000 px instead of 20,000 px, a 200x200 element at 15° counts 40,000 px instead of 60,000 px, a rotated `CanvasGroup` composited onto a 0.25x-scaled outer group counts its exact rotated area, and spinning elements keep constant overdraw across angles).
- **Draw calls (`totals.drawCalls`, `totals.staticDrawCalls`, `totals.batchBreaks`, `totals.batchBreaksByCause`):** `rur`'s own wgpu renderer uses an uber-shader that merges dissimilar primitives into very few batches; `rur cost` counts the draws the Roblox client makes instead, following its batching as measured in RenderDoc captures of a rendered Studio 0.747 client (195 scenes, 187 counted exactly; 13 of 14 held-out fixtures exact, the 14th one draw off). Consecutive pieces share a draw while their state matches: the pixel shader (fills, images, text, shadows, `Path2D` and `CanvasGroup` composites share one and differ only by texture; `UICorner` shapes and border `UIStroke`s use a rounded shader whose per-draw constants are the shape's snapped device size, its corner radii and stroke thickness; a `UIGradient` piece is always a draw of its own), the texture (each image URI is its own texture: the client does not atlas UI images; text of every font and size shares one glyph atlas; fills and borders share a white texture), a border `UIStroke`'s half-size as the client computes it in float32 from the frame's snapped edges kept as logical coordinates (so a row of identical strokes on fractional device pixels breaks at every power of two of its logical x: 1,300 strokes in rows of 49 at 1.5x draw 163 times), the sampler (`ResampleMode.Pixelated`), and the scissor. The client fills its vertex buffer in chunks of 10,000 vertices and starts a new draw at each chunk boundary (2,500 plain quads a draw). Rotation, transparency, colour and `PlayerGui`/`CoreGui` layers never break a batch. `drawCalls` is a frame that re-renders every `CanvasGroup`'s texture (the frame after a mount, or one where every group's content changed); `staticDrawCalls` is a frame where no group's content changed, which the client draws as each group's composite quad plus its border and border strokes. Both are informational in `rur cost compare` (verdicts stay comparable with reports saved before the calibration). Break causes:
  - `renderTarget`: entering or leaving a `CanvasGroup`'s composite quad.
  - `clip`: changing the active scissor clip rectangle inside the target (`ClipsDescendants` / scroll window / text self-clip).
  - `ownDraw`: a piece the client always draws alone (a `UIGradient` piece, an inset `UIShadow`).
  - `shader`: switching between the plain and rounded shaders.
  - `texture`: changing texture (image URI, glyph atlas, white, shadow profile) or sampler.
  - `constants`: the rounded shader with another size, radius or stroke thickness.
  - `batchLimit`: a 10,000-vertex chunk boundary (a border `UIStroke` is 16 vertices, 12 when it is 4 quads).

### 2. `CanvasGroup` offscreen render targets

Offscreen target sizing uses the exact Studio rules established in [images.md](images.md) (`native/src/render/geometry.rs::group_texture_dims`):

- Rectangular RGBA8 allocation `(nw, nh)` from the group's unrotated snapped device rectangle and float32 logical size (`nw * nh * 4` bytes). In captures of a Studio 0.747 client each group's texture is exactly that: `R8G8B8A8_UNORM`, `nw x nh`, one mip level, no multisampling; it is kept while the group is shown and re-rendered only when its content changes, freed with the group, and not reused for another group. (The driver's own row alignment is not visible to D3D11.)
- The group's background is drawn by its composite quad, not into the texture; its border and border `UIStroke`s are drawn on the parent target after the composite.
- Large groups scale uniformly so neither side exceeds `2048` device px and area stays within `2048 x 1024` px.
- Groups that are `culled`, `Visible = false`, zero-sized, or have quantized `alpha8(1 - GroupTransparency) == 0` allocate `0` bytes and perform `0` RT switches.
- Each drawn target counts `2` render-target switches (`totals.canvasRtSwitches`) and tracks nesting depth (`totals.maxCanvasGroupDepth`).
- **Offscreen texture clipping and texel area rules:** Matching `native/src/render/groups.rs::texture_clip_node` (Studio rule measured in [images.md](images.md), round 7), a `CanvasGroup`'s own background and its descendants are rendered into its offscreen texture clipped only by the group's bounds and any clipping frames *inside* the group — not by the group's ancestors (live runs resolve interior clips directly from the DOM hierarchy rather than heuristic edge-stripping, so nested `CanvasGroup`s and interior clips sharing an edge with an outer clip remain exact). The ancestor clip applies when compositing the group's texture onto its parent target. Inside a size-capped `CanvasGroup`, offscreen overdraw is scaled by `(nw / flat_w) * (nh / flat_h)` so it measures actual RT texels written rather than unscaled logical pixels.
  - **Non-comparability note:** Reports generated before this rule unified background and descendant clipping do not compare on `offscreenOverdrawViewports` (or `quads` / `clip` batch breaks) for `CanvasGroup`s clipped by an ancestor (including overhanging nested `CanvasGroup`s). Earlier builds either clipped both background and children to the ancestor or left the background unclipped while clipping children.

### 3. Hidden-in-shown DOM subtrees

Scene JSON omits descendants below `Visible = false` nodes. When `rur cost` runs a live story/fixture/module/model, it walks the live DOM under every enabled exported `ScreenGui` before engine teardown:

- `totals.hiddenInShown.roots`: top-most `Visible = false` `GuiObject`s inside enabled `ScreenGui`s.
- `totals.hiddenInShown.guiObjects`: total `GuiObject`s inside those hidden subtrees (including the hidden roots).
- `totals.hiddenInShown.instances`: total instances inside those hidden subtrees (including `Folder`s and UI modifiers).
- `totals.disabledScreenGuis` and `totals.disabledScreenGuiInstances`: `Enabled = false` `ScreenGui`s under `PlayerGui` / `CoreGui`, kept separate from `hiddenInShown` because disabled `ScreenGui`s are skipped by Roblox's layout and draw passes.
- `hiddenSubtrees`: the largest hidden-in-shown subtrees sorted deterministically by descendant count.

When invoked with `--scene <scene.json>`, `totals.hiddenInShown.complete` is `false` because descendants below hidden nodes are absent from `scene.json`.

### 4. Multi-frame sequence layout churn

In sequence mode (`rur cost --from/--to/--frames/--duration/--fps` or `rur sequence --cost`), each captured frame records:

- Incremental `Layout.Stats` counters for that frame (`passes`, `computed`, `memo`, `measures`, `stored`, `skipped`, `moved`, `texts`, `scrollPasses`, `scrollMoved`, `relaid`, `relaidUnder`, `resorted`). After a geometry write (a GuiObject's `Size`, `Position`, `AnchorPoint`, `Rotation`, `Visible`, `SizeConstraint` or `AutomaticSize`, a text input of a text object that sizes itself to its text, `LayoutOrder` beside a `UIGridLayout`, a layout object's or modifier's property such as `UIPadding` or `UIScale`, or a GuiObject put in or taken out) a client lays its ScreenGui's whole tree out again: `relaid` counts the unchanged objects the pass skips (the unchanged children of every object it lays out) and `relaidUnder` the records under those; a `Text`, `TextSize` or `Font` change in a fixed box, colours, `Name` and `LayoutOrder` without a layout object do not. A `ZIndex` write makes the client sort the tree's objects again: `resorted` counts the tree's records, once a frame. Static UI incurs `0` layout churn on frames `1..N`; animated or resizing UI reports the exact objects laid out each frame, and scrolling reports `scrollPasses` and `scrollMoved` separately from non-scroll `moved` records.
- `unchanged`, `changedNodes`, `removedNodes`, and full per-frame `totals` matching single-moment `rur cost --time <t>` when `fps` divides `60`.
- `sequence.summary`: `mean`, `peak`, and `p95` across all frames, plus steady-state (`frames[1..]`) layout churn mean and extrapolated layout CPU ms.
- `runMode` and `runModeInfo`: every `cost.json` records the engine run mode (`"play"`, `"edit"`, or `"scene"`) and its cadence.
  - **`rur cost` sequence mode defaults to `--mode play` at 60 Hz client cadence** (`--client-hz` defaults to `60`; 1 `Heartbeat` per client frame). `--fps` controls only how often samples are captured: steady-state layout counters and `layoutCpuMs` are always normalized per 1 client frame at `--client-hz` (for example, `--fps 30` steps 2 client frames per sample and divides by 2, and `--fps 120` alternates 0 and 1 client frames per sample and divides by the completed client frames). Any individual sample spanning `0` or `>1` client frames — or frame 0, or a run where `0` steady client frames completed — refuses `layoutCpuMs` rather than printing a non-client-frame figure as one client frame. Pass `--client-hz <Hz>` to simulate another client refresh rate explicitly (the report label prints the cadence that ran).
  - **Explicit `--mode edit`** (and `rur sequence --cost` without `--mode play`) runs Studio's 240 Hz edit-mode `Heartbeat` (4 beats per 60 Hz frame), which can fire Heartbeat-driven work up to 4x a client's rate. Because of this, `rur cost` **refuses** per-frame `layoutCpuMs` in `--mode edit` (`status: "refused"`, `ms: null`) and directs you to re-run with `--mode play`. Single-moment `rur cost` defaults to `--mode edit` (matching `rur render`) and already refuses per-frame `layoutCpuMs` in both modes.
  - **Failing, yielding, or empty-mount runs:** If a story errors, yields without returning, or mounts nothing (`status: "error"`, `"yielded"`, or `"empty"`), `rur cost` prints the unwrapped failure cause (skipping nested wrapper lines such as `error while running root():` / `effect error:` to surface the root error and user frame) or the exact yield location (`waitingAt`, with file and line) on stdout/stderr and in `cost.json`, refuses `layoutCpuMs` (never reporting `0.0000 ms` as a valid UI cost), and exits `2`. If the story drew UI and then yielded inside mount, the screen names the drawn node count and says where mount yielded and that mount must return first (only advising `task.spawn` or `Heartbeat:Connect` when the yield is an inline wait loop such as `while true do task.wait() end`), rather than claiming zero counts. When a story mounts in `--mode edit` but not `--mode play`, the play screen states that per-frame `layoutCpuMs` is unavailable as-is and points to `--mode edit` for static counts, while the `--mode edit` sequence probes play mode and prints that play-mode wait/error as the single fix rather than sending you back to `--mode play` in a circle. Conversely, when a default edit-mode single-moment (or `--mode edit` sequence) run fails or mounts empty, `rur cost` probes `--mode play` and notes `mounts in play mode, not edit (pass --mode play)` on the failing screen when play mode mounts it.

### 5. Attribution, extrapolation, and explicit refusals

- **Attribution:** `screenGuis` attributes draw calls, batch breaks, quads, glyph quads, CanvasGroup RT bytes/switches, overdraw, and hidden-in-shown counts per `ScreenGui` (enabled ScreenGuis sum conservatively to `totals`; disabled ScreenGuis appear with `enabled: false`). `objects` lists the heaviest drawn objects and `CanvasGroup`s.
- **Single-moment vs. per-frame layout CPU ms:**
  - Single-moment `rur cost` (without `--from`) only observes the export's full-tree layout pass (`fullTreeLayout`). It **refuses** `predicted.*.layoutCpuMs` (`status: "refused"`, `ms: null`) and directs you to run with `--from` and `--frames` for per-frame cost, while reporting the one-shot full-tree price separately under `predicted.*.fullTreeLayoutCpuMs` (`scope: "full_tree_export_pass"`).
  - `--scene` reports carry no layout counters and refuse `predicted.*.layoutCpuMs`.
- **Extrapolated layout CPU ms (`predicted.*.layoutCpuMs` in sequence mode, `fullTreeLayoutCpuMs` in single mode):**
  - `desktop-ref` (`basis: "extrapolated"`): prices the layout counters with slopes fitted to a rendered Studio 0.747 client's per-frame `UpdateUILayouts` (LibMP, checked against the frame log's uncaptured step CPU): `27 us` per layout or scroll pass + `1.22 us` per `stored` record + `1.30 us` per `moved` record + `0.12 us` per record a scroll moves (`scrollMoved`) + `17.7 us` per text laid out (`texts`) + `0.92 us` per `relaid` object + `0.19 us` per `relaidUnder` record + `0.19 us` per `resorted` record, naming the recording in `extrapolatedFrom`. Fitted over 83 single-factor scenes (card grids scrolled and edited, frame chains of depth 1 to 32, lists, moved subtrees, text, and one write of each kind among 100 to 3,000 objects; median error 13 %) and checked on four held-out animations (median error 42 %, three of them priced low). The client pays for every ancestor it lays out again (1.2 to 1.6 us per level of depth, measured), so ancestor records count like any stored record. A single moment's `fullTreeLayoutCpuMs` applies the same slopes to laying the whole tree out once (a mount is not measured against a client). The one-screen summary prints a `caveat:` line whenever extrapolated ms is shown (on steady sequences with layout drivers, with the share of steady records that are ancestors from `layoutDriverSummary.ancestorShare`; before-vs-after comparisons on one story remain valid).
  - `phone-mid` (`basis: "derived_extrapolation"`, `ratioBasis: "derived"`): scales `desktop-ref` by a derived ratio rather than a recorded layout ratio — `4.09` (range `2.65..8.0`, the phones' captured whole-UI-pass ms over a desktop client's captured ms) × `0.88..1.12` (the profiler capture's overhead on the desktop client's UI work, measured: captured `UpdateUILayouts` against the frame log's uncaptured step CPU, and the render call's CPU with and without a capture; `measured_desktop_ui_work`) × `0.77` (the frame-weighted live / capture-mean factor recorded for the phones' GUI category, `recorded_phone_gui_category`) = central range **`2.77x..3.53x`** (`rangeMs`, `ratioRange: [2.7714, 3.5272]`) and full band **`1.80x..6.90x`** (`bandMs`, `bandRatio: [1.7956, 6.8992]`). Reports `factors` (each with its basis) and `settledBy` (recorded phone timings of this work) instead of a single false-precision point number.
- **UI draw-pass CPU ms (`predicted.*.drawPassCpuMs`):** `desktop-ref` prices a static frame (`scope: "static_frame"`) by the pieces it draws onto the screen, with slopes measured on a rendered Studio 0.747 client on the reference desktop (LibMP `Pass2d + fillGuiVertices + UI + compositeUITextures` per render frame; the profiler capture did not change the render call's CPU): 20 us once any UI draws, 0.116 us a plain quad, 0.243 an image quad, 0.45 a sliced image quad, 0.145 a glyph, 0.226 an off-axis element, 1.5 a `UIShadow`, 0.2 a draw. `groupRerenderMs` adds a frame whose `CanvasGroup`s all re-render: 63 us and their content's pieces, which cost the client more drawn into a group's texture than on the screen (measured: 4.0x a frame's price, 3.5x a glyph's, 6.2x an image's; single-group scenes of 100 to 2,000 pieces within 10 %, median 7 %). Calibration scenes: median error 19 %; held-out fixtures: median 33 % (17 us), mostly priced low. `phone-mid` scales it by the derived phone ratio below.
- **Explicit refusals (`status: "refused"`, `ms: null`):** `gpuUiMs` is refused on both tiers: measured on the reference desktop GPU, a UI draw costs about 4 us plus 4.8 us per megapixel in RenderDoc replays at boost clocks, while the live client at 60 Hz spent 8.6x that on the same frames at its idle clocks, so desktop GPU ms follows the GPU's clock state, and a phone's tile-based GPU has no conversion from it. `drawPassCpuMs` is refused only where no frame was analysed (a failed or empty run). `unmodeled` enumerates all excluded cost dimensions.

## A/B comparison (`rur cost compare`)

`rur cost compare <before> <after>` runs an **equivalence gate** before emitting any verdict:

- **Input validation:** Both inputs must be well-formed `rur-cost/1` cost reports. Passing a non-cost file (such as `scene.json`, `summary.json`, `trace.json`, or a previous `rrr-ab/1` diff) exits non-zero with an error naming what the file is and what to run instead.
- **Equivalence checks:** `schema`, `status` (both `"ok"`), `source` (matching story/fixture/module/model target), `mode` (`single` vs. `sequence`, plus matching `--time` for live single moments and matching `from`, `frameCount`, `fps`, and `clientHz` for sequences), `runMode` (`play` vs. `edit` vs. `scene`), `input` (`live` vs. `scene`) and `totals.hiddenInShown.complete`, `viewport` (`width` and `height`), `scale`, `device` (`desktop`/`touch`/`gamepad`), and `controls` (compared by value so `1.0` and `1` match). Reports saved by earlier builds that lack `source`, `device`, `controls`, or single-moment `time` are never refused for a missing field alone; they compare and print a one-line `note:` naming which fields were not checked because the older report predates them. Any mismatch between present fields returns `verdict: "refused"` with `equivalence.passed: false`, lists every mismatch and remediation command, and exits non-zero. Unknown CLI options and unexpected positional arguments exit `64` immediately rather than being silently ignored, and `--time` rejects lists with an error noting that `rur cost` takes a single moment (use `--from` and `--frames`/`--to`/`--duration` with `--fps` for multiple moments).
- **Comparable arms (`rrr-ab/1`):**
  - `verdict`: `improved`, `regressed`, `mixed`, or `unchanged` (with `measurementNoise: 0.0`), driven only by measured counts (`quads`, `glyphQuads`, `canvasRtBytes`, screen/offscreen overdraw, `hiddenGuiObjects`, and sequence layout churn; `drawCalls`/`staticDrawCalls`/`batchBreaks` are informational only).
  - `equivalence`: `{ "passed": true, "checks": [...] }`.
  - `counts`: `before`, `after`, and `delta` across quads, glyph quads, CanvasGroup RT bytes/targets/switches, screen/offscreen overdraw, hidden-in-shown `GuiObject`s, and informational draw calls (re-rendering and static frames) / batch breaks.
  - `layout` and `predicted`: before/after/delta layout counters and extrapolated layout CPU ms.
  - `screenGuiMovers`: per-`ScreenGui` deltas for every layer whose counts changed.
